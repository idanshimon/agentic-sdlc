Reference architecture

Designing an agentic pipeline
that survives audit

A reference architecture for enterprise engineering teams — how to design a governed agentic pipeline, and how developers actually work inside it day to day.

Sample data throughout; every number describes seeded sample data, not live telemetry. Meridian is a fictional product used for illustration.

The problem

The question nobody can answer

The audit request

"Show me every decision an AI agent made about PHI handling this quarter, who approved each one, and which policy version applied."

What teams can produce today

  • git log — commits, no reasoning, no rule cited
  • a Slack thread — scrolled past, half the people gone
  • a screenshot — of a dashboard that has since changed

The gap between the ask and the evidence is where trust in agentic development breaks.

The shift

Two columns that no longer meet

What changed

  • Agents open PRs on their own
  • Agents write and refactor code
  • Agents make judgment calls at machine speed
  • Volume of decisions is now super-human

What didn't

  • Your regulator's evidence standard
  • Who-approved-what, and under which rule
  • Immutable, queryable, time-versioned proof
  • The burden falls on you, not the agent

The gap between those two columns is the entire problem.

The one idea

An agent decision is not an event to log.
It is a record to keep.

Events

For debugging. Rotated out, sampled, dropped. Nobody promises they survive the quarter.

Records

Immutable and queryable. You can ask them a question a year later and get the same answer.

The rule travels

A record carries its governing rule version, so the why is inside the artifact — not in someone's memory.

The scenario · Meridian patient portal

Three runs

RUN 1 · human lead

Sets four precedents

  • PHI classification
  • Auth policy
  • Retention
  • Naming
RUN 2 · agents

Reuse precedents

Agents apply the four precedents correctly across a new module — citing the same rule versions.

RUN 3 · agent error

Sets billing retention to 3y

Clinical standard is 7y. A human catches it, flags it — and autopilot pauses for that entire decision class.

The agent was wrong. That is not the story.
The system noticed, and stopped itself.

Why it scales

Four properties that compound

a · Precedent reuse

Decision cost falls as the corpus grows — each answer is reusable.

b · One source of law

Standards live in one versioned place, not scattered across N prompts.

c · Plug-in surfaces

New agent surfaces adopt the same ledger contract — no bespoke governance.

d · Per-class gate

Autonomy expands where trust is earned, contracts where it is not.

It meets the platform you already run

GitHub Agentic Workflows technical preview · Feb 2026

gh-aw (GitHub Next + Microsoft Research + Azure Core Upstream). Agents run read-only; writes go through declared safe-outputs, executed by a separate permission-controlled job.

safe-outputs controls whether a write happens. It does not record why the decision was made, which rule governed it, or what precedent it reused.

So gh-aw becomes a fourth writer surface into the same ledger — the two are complementary, not competing.

--- .github/workflows/triage.md ---
on: issues
permissions:
  contents: read
safe-outputs:
  add-comment:
    max: 1
  add-labels:
    allowed: ["triage","needs-info"]
---
Read the issue, classify it, and
propose one label from the allowed set.
What we got wrong

The trust beat

Feature with no consumer

We built a rewind/reopen feature whose state nothing read. We shipped it disabled rather than ship the lie.

One axis, two meanings

A run-flow view where one axis meant two different things by row. A correctness bug — found and fixed.

Empty graphs, green tests

Three graph views shipped rendering completely empty (a missing data fallback) — and the full suite stayed green throughout.

Tests certify shape. Only looking certifies truth.

The test

Judge this on one query

Pick any agent decision from the last quarter and ask the system why it was made. You should get the rule version, the human who approved it, and the precedent it reused — in one hop.

Agents will be wrong.
The question is whether your system can notice.
